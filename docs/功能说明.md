## 1. 产品定位

**REDMI K100 PRO MAX 音质控制台**是一个针对 REDMI K100 Pro Max（代号 songyuan）的 Dolby DAX3 全链路调音模块。

它不做以下事情：

- 不修改扬声器硬件、不改变功放保护策略；
- 不替换系统音频 HAL，不注入第三方音效驱动；
- 不联网、不上传音频、不收集使用数据。

它主要做三件事：

1. **重写 Dolby DAX3 配置**：把 20 段目标曲线写入 10 个 IEQ / GEQ 槽位，生成完整可用的 `dax-default.xml`，同源覆盖 `Link/`、`vendor/`、`factory/` 三份副本并 bind 到系统路径。
2. **提供可视化调音台**：在 Root 管理器的 WebUI 中直接拖曲线、拉滑杆、选槽位、改属性、应用写入，不需要手工改 XML。
3. **提供可选的 OTG 常开能力**：默认关闭；开启后可开机自动打开 OTG，并由守护进程防止系统 10 分钟无操作自动关闭。

设计原则：

- **默认安全**：安装前做机型 / 系统 / Dolby 配置 / MD5 校验，不匹配直接终止，不修改任何文件。
- **默认好听**：出厂默认曲线为“K100PM 调整版”，低频扎实、人声凝聚、声场开阔。
- **默认轻量**：首屏一次 `snapshot` 拿全数据，热路径零 fork，WebUI 首屏 0.2–0.3 秒。
- **可恢复**：保留出厂备份、原厂曲线与卸载脚本，随时可以恢复。

## 3. 适用设备与兼容性

### 3.1 支持范围

| 项目 | 要求 |
| --- | --- |
| 机型 | REDMI K100 Pro Max（`ro.product.model=M098FE`，市场名含 K100） |
| 设备代号 | `songyuan`（`ro.product.device` / `ro.build.product` / `ro.product.odm.device` 任一匹配） |
| 系统 | Android 15+（API 35+）；实测 HyperOS V816 / API 37 |
| 音频 | 系统存在 Dolby DAX3 配置（`dax-default.xml`） |
| Root | KernelSU / SukiSU Ultra / APatch；Magisk 安装层面兼容（minMagisk 20400），WebUI 需 MMRL / WebUI X 等宿主 |
| WebUI 宿主 | KernelSU WebUI、SukiSU Ultra、APatch、MMRL、WebUI X |

> 实测设备：REDMI K100 Pro Max / songyuan / HyperOS V816 OS4.0 / API 37。不同地区版本、不同 ROM 的节点名或 Dolby 文件可能不同，安装脚本会直接拒绝不匹配的设备。

### 3.2 不支持的情况

- 非 K100 Pro Max / 非 songyuan 设备；
- Android 15 以下（API < 35）；
- 系统没有 Dolby DAX3 配置，或 Dolby 文件被其他模块替换；
- 安装包内目标 XML 的 MD5 与当前系统不一致（说明 ROM 版本不同，强行写入有风险）；
- 只想要“通用音效增强”、不愿承担 Root 模块风险的用户。

安装脚本的校验发生在**任何删除、stash、覆盖操作之前**，不匹配时会：

1. 打印具体失败原因（设备 / 机型 / API / Dolby / MD5）；
2. 直接 `abort`；
3. 不修改旧模块、不删除用户曲线、不写入系统文件。

## 4. 安装、升级与卸载

### 4.1 安装前检查

1. 确认机型是 REDMI K100 Pro Max；
2. 确认系统是 Android 15+，并且 Dolby 音频正常；
3. 确认 Root 管理器支持模块安装（KernelSU / SukiSU Ultra / APatch / Magisk）；
4. 备份当前模块的自定义曲线（如果从旧版本升级）；
5. 下载对应版本的 zip，不要解压后刷入。

### 4.2 安装流程

1. 在 Root 管理器中点“从本地安装”，选择 `REDMI_K100_PRO_MAX_音质控制台_v1.0_WebUI.zip`；
2. 安装脚本显示横幅与校验结果；
3. 校验通过后：
   - 备份当前 Dolby 配置到 `data/backup/`；
   - 写入模块文件；
   - 保留 / 迁移用户数据（曲线、槽位、属性、OTG 配置）；
   - 设置权限与 SELinux 上下文；
4. 重启手机（首次安装建议重启，确保 bind 与属性生效）；
5. 在模块列表点“打开”进入 WebUI。

### 4.3 升级行为

从旧版本升级时，安装脚本会保留：

- `data/curves/` 下的自定义曲线；
- `data/slots.conf` 的槽位映射；
- `data/props.conf` 的属性值；
- `data/otg.conf` 的 OTG 配置（自定义过的配置保留）。

从 v1.5C 升级到 1.0 时：

- 如果 `otg.conf` 仍是 v1.5C 的出厂默认（`AUTO_ON=1`、`KEEP_ON=1`、`INTERVAL=30`、无自定义 NODE），会自动切换为 1.0 的默认关闭（`0/0/30`）；
- 如果用户改过 OTG 配置，则原样保留，避免覆盖用户选择。

### 4.4 卸载

在 Root 管理器中卸载模块，或执行卸载脚本。卸载会：

- 解除 `/odm`、`/vendor` 下的 bind 挂载；
- 停止 OTG 守护进程；
- 清理模块目录与临时文件；
- 重启后彻底失效。

卸载不会自动恢复系统 Dolby 配置；如需恢复原厂音效，请在卸载前进入“运行状态 → 恢复原厂曲线”，或使用 `k100pm.sh reset`。

### 4.5 安装失败 / 无法开机时

- 在 Root 管理器的安全模式或“禁用模块”功能中禁用本模块；
- 或进入 Recovery 删除 `/data/adb/modules/k100pm_audio_plus`；
- 本次安装校验失败不会修改任何文件，直接重新下载正确版本即可。

## 5. 快速开始

### 5.1 第一次打开

1. 安装并重启；
2. 模块列表 → REDMI K100 PRO MAX 音质控制台 → 打开；
3. WebUI 发出 **1 次** `snapshot`，同时取回状态、曲线、槽位、属性；
4. 首屏先画出 20 段骨架，再填入真实数据，通常 0.2–0.3 秒可交互；
5. 如果显示“预览模式”，说明当前不是 Root 管理器 WebUI 环境，只演示、不写入。

### 5.2 调一次音

1. 在“调音台”拖动曲线节点，或拖动下方 20 段滑杆；
2. 看“编辑中”与脏点，确认当前改动尚未写入；
3. 想保留这套数值：点“保存为曲线”，起一个名字；
4. 想立即生效：点“应用并写入”，模块会写入 10 个槽位并生成 XML；
5. 到“运行状态”点“完整性自检”，确认三份配置一致；
6. 如需立刻听到变化，点“重启音频服务”；重启手机最彻底。

### 5.3 恢复默认

- 单条曲线：在“20 段增益”卡片点“恢复”，回到当前槽位的曲线值；
- 全部归零：点“全部归零”；
- 恢复原厂：运行状态 → 恢复原厂曲线；
- 恢复默认调音：把 10 个槽位都指回 `K100PM 调整版`，再应用。

### 5.4 开启 OTG 常开（可选）

1. 进入“OTG”页；
2. 打开“开机自动开启”和“保持常开”；
3. 设置复查间隔（默认 30 秒）；
4. 点“保存”；
5. 需要立即生效时点“立即开启”；
6. 不需要时关闭两个开关并保存，或点“关闭”。

## 6. WebUI 功能详解

WebUI 由模块自带的 `webroot/index.html` 加载，完全离线。页面顶部的 6 个 Tab 分别是：**调音台、曲线库、DAX 属性、OTG、运行状态、日志**。

### 6.1 调音台

#### 6.1.1 频响曲线编辑器

- 20 个固定频点：47、141、234、328、469、656、844、1031、1313、1688、2250、3000、3750、4688、5813、7125、9000、11250、13875、19688 Hz；
- 对数频率轴，纵轴 ±20 dB；
- 拖拽节点改增益；双击节点归零；
- 实时提示频率与增益；
- “参考线”开关叠加显示 `K100PM 基准曲线`，方便对照调整量；
- 当前曲线与参考曲线在图例中分别显示名称。

#### 6.1.2 20 段滑杆

- 每段一根滑杆 + 一个数值输入框；
- 滑杆步进 0.05 dB，数值输入支持 0.01 dB；
- 范围 ±20 dB，超出会被裁剪；
- 与曲线图双向联动；
- “恢复”按钮：回到当前槽位实际使用的曲线值；
- “全部归零”：20 段全部设为 0 dB；
- 增益区带自愈重建：行缺失、数量不符或被移出 DOM 时自动重建，始终保持 20 段。

#### 6.1.3 保存为曲线

- 点“保存为曲线”输入显示名称，曲线 ID 自动生成（`custom_<时间>`）；
- 校验 20 个整数、范围 ±2000（即 ±20.00 dB）；
- 保存到 `data/curves/<id>.gains` 等文件；
- 内置曲线不可覆盖；自定义曲线可删除；
- 保存不会自动写入系统，需要再点“应用并写入”。

#### 6.1.4 应用并写入

- 如果当前曲线尚未保存，会先弹出命名框保存为自定义曲线；然后把 10 个槽位（IEQ1–3 + GEQ0–6）全部指向该曲线；
- 重新生成 `dax-default.xml`；
- 结构自检：60 段 IEQ、140 段 GEQ、10 个 preset、结尾完整、无残留标记；
- 同源写入 `Link/`、`vendor/`、`factory/`；
- 刷新 bind 挂载（如未挂载会自动补）；
- 写入 `data/state/applied` 记录；
- 底部浮动条与标题脏点消失，表示已落盘。

#### 6.1.5 槽位映射

- 10 个槽位：IEQ 1/2/3（Dolby 内容 IEQ 目标曲线）与 GEQ 0–6（图形均衡预设）；
- 每个槽位可单独选择曲线；
- 快捷按钮只改本地待写入的映射，不会立即落盘：
  - “全部 = 当前曲线”：10 个槽位都指向当前曲线；
  - “仅 IEQ”：只改 IEQ1–3；
  - “仅 GEQ”：只改 GEQ0–6；
  - “恢复原厂映射”：回到出厂槽位映射；
- “写入槽位配置”会把当前映射通过 `assign-map` 写入 `data/slots.conf`，并立即执行 `apply` 生成 XML，不需要再点一次“应用并写入”；
- “写入槽位配置”按当前逐槽位映射写入；
- “应用并写入”先把 10 个槽位全部指向当前编辑曲线，再写入；
- 两者都会生成 XML、写入三份副本并刷新 bind。

#### 6.1.6 未写入提示

- 底部浮动条提示“有未写入的改动”；
- 标题旁的小圆点（脏点）表示当前编辑内容尚未落盘；
- 切换 Tab 不会丢失编辑中的曲线；
- 关闭页面前请先保存或应用。

### 6.2 曲线库

内置 13 条曲线：

| 分类 | 曲线 |
| --- | --- |
| 默认 | `K100PM 调整版`（DEFAULT） |
| 基准 | `K100PM 基准曲线`（BASE） |
| 平直 | `平直参考线` |
| 原厂 IEQ | `orig_ieq_detailed`、`orig_ieq_balanced`、`orig_ieq_warm` |
| 原厂 GEQ | `orig_geq_0` – `orig_geq_6`（7 条） |

每条曲线显示：

- 名称与来源标签；
- 迷你频响缩略图；
- 最大 / 最小增益；
- 是否内置（内置不可删除）。

导入：

- 支持 `gains_q4`、`gains`、`gains_db`、`bands[].gain` 四种字段；
- 自动校验 20 段与频点；
- 超出 ±20 dB 会被裁剪；
- 导入后保存为自定义曲线，不会自动写入系统。

导出：

- 导出到 `/sdcard/Download/k100pm_<id>.json`；
- 可用于备份、分享、跨设备迁移；
- 导出内容包含 20 段增益与曲线元信息。

删除：

- 仅自定义曲线可删除；
- 删除前需确认；
- 内置曲线不可删除。

### 6.3 DAX 属性

- 读取 `data/props.conf`，共 22 项 Dolby / 低功耗属性；
- 按分组展示：低音、虚拟环绕、音量、低功耗、其他；
- 修改后点“保存并应用”：
  - 写回 `props.conf`；
  - 通过 `resetprop` 立即生效；
- `ro.*` 音量阶数、安全音量等属性由 `system.prop` 开机注入，不在本页修改；
- 属性改动不会改变曲线 XML，但会影响 Dolby 的运行时行为。

### 6.4 运行状态

显示内容：

| 区块 | 内容 |
| --- | --- |
| 模块 | 版本、versionCode、作者、模块路径 |
| 设备 | 机型、代号、Android 版本、API、Root 类型 |
| 配置 | 当前槽位、配置哈希、上次写入时间、是否同步 |
| 挂载链路 | 模块文件 → bind 挂载 → 系统路径 |
| 自检 | 模板、10 槽位、三份哈希一致、DAX 结构、出厂备份、WebUI 资源、运行态挂载 |

完整性自检的 7 项：

1. 配置模板存在且结构正确；
2. 10 个槽位映射完整；
3. `Link/`、`vendor/`、`factory/` 三份配置哈希一致；
4. DAX 结构为 60 段 IEQ / 140 段 GEQ；
5. 出厂备份存在；
6. WebUI 资源完整；
7. 运行态 bind 挂载正常。

> 在开发工作区里，“运行态挂载”可能显示 FAIL，这是未安装到 `/data/adb/modules` 的正常现象；真机安装后应为 PASS。

维护操作：

- **重启音频服务**：让新曲线尽快生效；
- **恢复原厂曲线**：把三份配置恢复为出厂备份；
- **重启手机**：最彻底，推荐在大量改槽位后使用。

### 6.5 日志

两个日志文件：

- `/data/local/tmp/k100pm_audio.log`：开机阶段（`post-fs-data.sh`、`service.sh`）；
- `/data/local/tmp/k100pm_webui.log`：WebUI 操作与 CLI 调用。

功能：

- 日志页按行展示；
- 支持 4 秒自动刷新；
- 用于排查“为什么没有写入”“OTG 为什么没开”“bind 是否成功”等问题；
- 日志只在本机，不上传。

### 6.6 OTG

#### 6.6.1 默认行为

- 1.0 默认 **关闭**：`AUTO_ON=0`、`KEEP_ON=0`；
- 默认不写节点、不启动守护进程；
- 需要时在 OTG 页手动开启。

#### 6.6.2 开启后的行为

- **开机自动开启**：`service.sh` 调用 `k100pm.sh otg boot`，把节点写为 1；
- **保持常开**：守护进程每 `INTERVAL` 秒读取一次节点，发现被系统 / HAL 关闭就重新打开；
- **默认复查间隔**：30 秒，可在 5–3600 秒之间调整；
- **配置持久化**：`data/otg.conf`；
- **单实例**：通过 `/proc/<pid>/cmdline` 校验，避免重复启动；
- **stale PID 保护**：PID 被复用时不会误杀其他进程。

#### 6.6.3 节点

- 真机节点：`/sys/class/xm_power/typec/cc_toggle`；
- 系统 Settings 的 `OtgUtils.isChecked/setCheck` 也是读写该节点；
- 不同 ROM 节点名可能不同，可在 `data/otg.conf` 用 `NODE=/sys/...` 指定；
- “诊断”会输出 `/sys/class/xm_power/typec/` 下的节点、权限、候选值、相关属性 / Settings、SELinux 上下文。

#### 6.6.4 关闭

- 关闭“开机自动开启”和“保持常开”，保存；
- 或点“关闭”；
- 如果保持常开仍启用，关闭时会二次确认，并一并关闭保持常开，避免被守护进程立刻重开。

#### 6.6.5 注意事项

- OTG 开启后手机处于 USB Host 模式，连接电脑可能无法被识别为存储设备；
- 需要连电脑时先关闭 OTG，或把 `KEEP_ON` 设为 0；
- 常开 OTG 会增加待机耗电；
- 不是所有 ROM 都允许用户态写该节点；写失败时看诊断与 SELinux 上下文。

### 6.7 预览模式与初始化失败

**预览模式**：

- 直接用浏览器打开 `webroot/index.html` 时触发；
- 界面、交互、演示数据完整；
- 不写入设备；
- 顶部会显示“预览模式”横幅。

## 7. 音频与配置架构

### 7.1 DAX3 结构

- 系统 Dolby 配置为 `dax-default.xml`；
- 模块保留原始结构模板 `data/dax.template.xml`；
- 模板中有 10 个槽位标记（`<!--#K100PM:IEQ1#-->` 等）；
- `k100pm.sh apply` 读取 `data/slots.conf`，从 `data/curves/<id>.gains` 取 20 段增益，生成：
  - `<ieq-bands>`：60 段 IEQ；
  - `<graphic-equalizer-bands>`：140 段 GEQ；
  - 10 个 preset；
- 生成后做结构自检，确保没有残留标记、结尾完整。

### 7.2 写入链路

1. 生成到临时文件；
2. 同源写入 `Link/`、`vendor/`、`factory/` 三份副本；
3. 保持 SELinux 上下文 `vendor_configs_file`；
4. 已存在的 bind 挂载直接读到新内容；
5. 未挂载时自动补 bind；
6. 记录 `data/state/applied`（哈希、大小、时间、同步状态）。

### 7.3 10 个槽位

| 槽位 | 用途 |
| --- | --- |
| IEQ1 / IEQ2 / IEQ3 | Dolby 内容 IEQ 目标曲线 |
| GEQ0 – GEQ6 | 图形均衡预设 |

说明：模块 `profile` 中 `ieq-enable=false`，因此 IEQ 曲线默认不参与实时处理（不会与 GEQ 叠加）；GEQ 为启用状态，默认曲线经由 GEQ 生效。若在 Dolby 界面手动开启 IEQ，请自行评估叠加量。

### 7.4 文件结构


## 10. 性能设计

### 10.1 实测对比

同一份配置、同一台 REDMI K100 Pro Max / Android 15：

| 操作 | v1.4C | v1.4D / 1.0 | 提升 |
| --- | --- | --- | --- |
| 打开 WebUI（首次 `snapshot`） | 5.2–7.3 s | **0.17–0.28 s** | ≈ 30× |
| 写入配置 `apply` | 14.5 s | **0.39 s** | ≈ 37× |
| 刷新状态 / 曲线库 / 属性 | 1.3–2.2 s | **0.05–0.08 s** | 20×+ |
| 写入 10 个槽位 | 最多 10 次 shell 调用 | **1 次**（`assign-map`） | ≤ 10× |
| 保存多项 DAX 属性 | 每项 1 次 shell 调用 | **1 次**（`set-props`） | N× |

> 数据来自本机 `date +%s%N` 计时与 5 次重复测量的中位区间；不同 Root 管理器、存储状态会有少量浮动，但量级一致。

### 10.2 为什么旧版慢

1. **`printf` 是外部命令**：Android 的 `/system/bin/sh`（mksh）里 `read` / `case` / `echo` / `print` 是内建，`printf` 每次都要 fork（本机 ≈ 6–8 ms）。旧版 `snapshot` 约 600 次 fork。
2. **每个 JSON 字段都走 `printf | tr | sed`**：一个字段 4–5 次 fork，22 项属性 ≈ 2.1 秒。
3. **应用模板逐行 `printf`**：3000 行模板 ≈ 14 秒。

### 10.3 1.0 的做法

1. **热路径零 fork**：用 `print -rn --` / `read` / `case` 内建拼 JSON；
2. **一次 exec 拿全首屏**：`snapshot` 同时返回 status + curves + slots + props；
3. **`getprop` 只跑一次**：`getprop | grep -F` 过滤后纯 shell 解析 22 项；
4. **文件解析去管道**：曲线 20 段用 `read` 一次读入；`/proc/mounts` 只读一次，用 `-ef` 判断同源；
5. **前端骨架先行**：先画 20 段骨架，再填真实数据；非当前 Tab 懒渲染；
6. **Canvas 降载**：网格 / 刻度预渲染到离屏画布，DPR 封顶 2×，去 `shadowBlur`；
7. **CSS 去掉 `backdrop-filter`**：顶栏 / 标签栏 / 弹窗改实色，滚动不再每帧重算模糊；
8. **批量写命令**：`assign-map` 一次写完整映射，`set-props` 一次写多项属性。

### 10.4 使用建议

- 首次打开等 `snapshot` 完成再操作；
- 不要在应用过程中连续点“应用并写入”；
- 大量改槽位后重启音频服务，或重启手机；
- OTG 常开会增加待机耗电，不用时关闭。

## 11. 安全、可靠性与恢复

### 11.1 安装安全

- 五重校验：设备代号、机型、API、Dolby 文件、目标 XML MD5；
- 校验在任何删除 / stash / 覆盖之前；
- 不匹配直接 abort，不修改任何文件；
- 安装包内 `Link/` 与 `vendor/` 的目标 XML MD5 必须一致；
- 安装脚本会保留用户曲线、槽位、属性、OTG 配置。

### 11.2 写入安全

- 生成后做结构自检：60 IEQ / 140 GEQ / 10 preset / 无残留标记 / 结尾完整；
- 三份副本同源写入，避免只改一份导致链路不一致；
- 保持 SELinux 上下文；
- 写入 `data/state/applied` 记录，便于核对；
- 出厂备份 `data/backup/dax-default.orig.xml` 可用于恢复。

### 11.3 恢复手段

| 场景 | 方法 |
| --- | --- |
| 调音不满意 | 调音台 → 恢复；或运行状态 → 恢复原厂曲线 |
| 槽位映射乱了 | 槽位映射 → 恢复原厂映射 |
| 属性改错 | DAX 属性 → 恢复默认（或重新安装） |
| 模块导致异常 | Root 管理器禁用模块 / Recovery 删除模块目录 |
| 想彻底还原 | 卸载模块 → 重启 |

### 11.4 隐私

- WebUI 完全离线，不请求任何网络资源；
- 不上传音频、曲线、日志、设备信息；
- 日志只写入 `/data/local/tmp/`；
- 模块不包含遥测 / 统计 SDK。

### 11.5 风险提示

- Root 模块有导致无法开机的风险，请确保有 Recovery / 安全模式手段；
- 不同 ROM 的 Dolby 配置可能不同，安装校验失败时不要强行改脚本绕过；
- OTG 常开会影响 USB 连接与待机耗电；
- 修改系统音频配置可能影响扬声器保护策略，请勿把增益长期推到极端值。

## 13. 常见问题（FAQ）

**Q1：刷入后模块列表里没有 WebUI 按钮？**  
A：确认 Root 管理器支持 WebUI（KernelSU / SukiSU Ultra / APatch / MMRL / WebUI X），并确认模块已启用、已重启。

**Q2：打开 WebUI 显示“预览模式”？**  
A：说明当前不是 Root 管理器的 WebUI 环境（例如用浏览器直接打开 `index.html`）。预览模式只演示，不写入。

**Q3：显示“初始化失败 / 无法连接模块命令”？**  
A：检查模块是否安装到 `/data/adb/modules/k100pm_audio_plus`、模块是否被停用、KernelSU 版本是否过旧；点“复制诊断信息”可查看详情。

**Q4：点了“应用并写入”，但听不出变化？**  
A：先到“运行状态”看配置哈希与三份配置是否一致，再点“重启音频服务”；部分场景需要重启手机。也请确认当前槽位使用的是你改的曲线。

**Q5：20 段增益最大只能到 20 dB？**  
A：1.0 的硬上限是 ±20 dB，滑杆、数值输入、导入、CLI 都会裁剪；这是为避免极端增益损坏扬声器。

**Q6：OTG 页显示“未检测到节点”？**  
A：点“诊断”查看 `/sys/class/xm_power/typec/` 下的节点与权限；不同 ROM 节点名可能不同，可在 `data/otg.conf` 用 `NODE=/sys/...` 指定。

**Q7：开启 OTG 后电脑识别不到手机？**  
A：OTG 是 USB Host 模式，连电脑时请先关闭 OTG，或把 `KEEP_ON` 设为 0。

**Q8：升级 1.0 后 OTG 自己关了？**  
A：1.0 默认关闭；如果旧配置是 v1.5C 的出厂默认（1/1/30），升级会自动切到关闭；自定义过的配置会保留。到 OTG 页重新开启即可。

**Q9：导入 JSON 失败？**  
A：确认是 20 段，支持 `gains_q4`、`gains`、`gains_db`、`bands[].gain`；数值范围 ±2000（±20 dB）；频点需与 20 段计划一致。

**Q10：怎么完全恢复原厂？**  
A：运行状态 → 恢复原厂曲线；或卸载模块并重启。卸载前建议先恢复原厂曲线。

**Q11：支持其他机型吗？**  
A：不支持。安装脚本会校验 songyuan / M098FE / K100 / API 35+ / Dolby 文件 / MD5，不匹配直接终止。

**Q12：模块会联网吗？**  
A：不会。WebUI 完全离线，不请求网络资源，不上传任何数据。
